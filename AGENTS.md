# AGENTS.md: working on Orbit

Instructions for coding agents (and people) changing Orbit. It is written so that one read is enough for the common
jobs: **adding an app**, changing one, and **releasing**. Each job is a checklist that names every file to touch, in
order. Follow the checklist instead of exploring the repository. Read code only where a step says to.

---

## 1. What Orbit is (60-second map)

Orbit installs, updates and controls a small set of apps (YTM Starcast, Nova, YTDL-UI, xmas-tui) from their GitHub
releases. It comes as a desktop program (Linux, Windows, macOS) and an Android app.

| Path | What it is | Status |
|---|---|---|
| `desktop/` | **The desktop Orbit (Rust).** It serves the page and API on 127.0.0.1 and shows them in its own window. | **The product: change this.** |
| `orbit/static/index.html` | **The whole desktop UI** (one file: CSS, HTML, JS). It is built into the Rust program. | The product. |
| `orbit/static/apps/*.svg` | App icons (generated by `tools/sync-icons.py`, never edited by hand). | Generated. |
| `orbit/static/i18n/*.json` | Translations: `{"English text": "translation"}`. | Must stay complete (tests fail otherwise). |
| `orbit/*.py`, `orbit/apps/`, `orbit/install/` | The older Python edition of the desktop Orbit. It serves the same `index.html`, and its tests still run. | Legacy: keep it working, but don't add apps to it. |
| `android/` | The Android Orbit (Kotlin, Compose). It installs the apps' Android APKs. | The product. CI compiles and runs it. |
| `packaging/catalog.json` | **The catalog** (generated by `tools/make-catalog.py`). Every installed Orbit reads it from `main`. | Generated. |
| `packaging/release-notes.md` | The text of the next GitHub release. | Hand-written. |
| `tools/` | Generators and CI scripts (see §3). | |
| `tests/` | Python tests: the legacy edition, the catalog, icons, translations and installs (with fakes). | |

**Two layers per app on the desktop.** Keep them apart:

- **Recipe** (`desktop/src/recipes/<id>.rs`, trait `Recipe` in `desktop/src/recipe.rs`): *installing*. It says which
  systems the app runs on, whether it is installed and at which version, what the computer needs, which choices to
  offer, and the install, update and remove steps. The installer window is drawn entirely from it.
- **App page** (`desktop/src/apps/<id>.rs`, trait `App` in `desktop/src/apps/mod.rs`): *using it once installed*. It
  gives the status, actions (buttons), the settings that Orbit can see and change, logs, and the way into the app's
  own settings.

An app can have only a recipe, but an app page is what gives it a status on its card, a side-bar tile and a settings
button: give every installable app both layers.

## 2. Ground rules

1. **Never change the real machine while developing.** Use `--dry-run`: the engine logs what it would do and
   changes nothing. Use the fakes in `tests/`. Don't install, update, start or stop the real apps on a developer
   machine. Several of them play sound or change audio.
2. **Every UI string must be translated** into all languages before CI passes (see §6). Plan for it in the same
   change.
3. **Generated files are never edited by hand**: `packaging/catalog.json`, `orbit/static/apps/*.svg`, and
   `android/app/src/main/assets/i18n/*.json` and `assets/icons/*`. Change the generator's input and rerun it.
4. **Check before you assert.** Run the tests and a dry run. Say what you ran and what you didn't (for example,
   Android only compiles and runs in CI).
5. **Security posture stays as it is.** Orbit listens on 127.0.0.1 only. Downloads come only from the app's own
   GitHub release, are checked against the release's checksums (and its signature where the app signs), and are
   refused if they come from anywhere else (`Session::asset`). Signing keys are built into the code and never come
   from the catalog.
6. **Commits and docs are written for end users.** Write no working notes in the repository. Commits carry no
   co-author trailers or "generated by" lines. Never commit tokens, keys, personal hostnames, IPs or emails.
7. **Text style** (the UI, notes, docs): plain, short and friendly. Use lowercase button labels ("install", "open
   settings"). Write no plurals with a "(s)" suffix: write separate singular and plural texts.

## 3. Commands

```bash
python3 -W error::ResourceWarning -m unittest discover -s tests -t .   # Python tests (~1 min, fakes only)
cd desktop && cargo test                                               # Rust unit tests
cd desktop && cargo build && ./target/debug/orbit --dry-run --no-window --port 8811   # a safe live run: open http://localhost:8811
XDG_CONFIG_HOME=/tmp/orbit-cfg ./target/debug/orbit --dry-run --no-window --port 8811 # …with throwaway Orbit settings
python3 tools/sync-icons.py [--check]     # pull each app's icon from its own repository (needs gh, signed in)
python3 tools/make-catalog.py [--check]   # rebuild packaging/catalog.json from its APPS list and the icons
python3 tools/i18n.py check               # every language has every text (also run by the tests)
python3 tools/i18n.py missing de          # what German lacks, as N<TAB>text
python3 tools/i18n.py merge de <list> <file>   # add translations (N<TAB>translation) for a `missing` list
python3 tools/i18n.py sync                # copy translations to the Android app (then `check` again)
```

The page is built into the program (`include_bytes!`), so **rebuild and restart** after editing `index.html`. A dry
run still writes *Orbit's own* settings (theme, order and so on). Point `XDG_CONFIG_HOME` at a scratch folder when you
click through settings.

## 4. Adding an app (desktop and Android)

Gather these first. They are the inputs for every step below:

| Input | Example (YTDL-UI) |
|---|---|
| id (lowercase, dashes) | `ytdl-ui` |
| Display name | `YTDL-UI` |
| GitHub repository | `JustAyden/YTDL-UI` |
| One-line description (blurb) | `Download video and audio from YouTube and 1,800+ other sites, in your browser (yt-dlp and ffmpeg)` |
| Brand colour | `#22d3ee` |
| Icon path(s) in its repository (SVG preferred, PNG fine) | `static/img/icon.svg` |
| Release files per system, and the checksum file | `ytdl-ui-linux-x64`…, `SHA256SUMS.txt` |
| Where it installs, how it runs (service, task, window), how to tell its version | folder + `/api/health` |
| Where its settings live (a file Orbit can read, or only inside the app) | `config.ini` + `data/settings.json` |
| Android: package id(s), APK file name, checksum file, signing key (if it signs) | n/a |

### Step 1: catalog entry (name, blurb, colour, icon, Android listing)

Edit the `APPS` list in `tools/make-catalog.py`. Copy an existing entry. Add `"android": {...}` only if the app has
an APK:

```python
{"id": "my-app", "name": "My App", "blurb": "What it does, in one line",
 "repo": "owner/my-app", "color": "#rrggbb", "icon": "apps/my-app.svg",
 "android": {"pkgs": ["com.example.myapp"], "apk": ["my-app.apk", "re:my-app-v[^/]*\\.apk"],
             "sums": "SHA256SUMS", "note": "One line shown before installing.", "extra": "Optional second line."}},
```

The catalog reaches every Orbit already installed within 12 hours of being pushed to `main`, without a release. That
covers names, blurbs, colours, icons and Android listings. Code changes (recipes, pages) need a release.

### Step 2: icon

Add one line to `ICONS` in `tools/sync-icons.py`:

```python
"my-app.svg": ("owner/my-app", ["path/icon.svg", "path/icon-192.png"], False),   # True only if Android has it built in
```

List paths newest first. The first one that exists is used, and a PNG is wrapped in an SVG automatically (keep it
small: 192 px, under about 45 KB). Then run `python3 tools/sync-icons.py && python3 tools/make-catalog.py`. CI fails
when an icon no longer matches the app's repository: rerun these two commands.

### Step 3: install recipe (`desktop/src/recipes/my_app.rs`)

Copy the closest existing recipe and adapt it:

- `recipes/ytdl_ui.rs`: a single program file per system, plus an optional background service and a menu entry.
  **The best template.**
- `recipes/xmas_tui.rs`: runs the app's own installer script or setup, and installs things the computer needs
  (with the administrator's password).
- `recipes/nova.rs`: a Debian package plus a signed release (ed25519 signature check).
- `recipes/starcast.rs`: a Python wheel, and moving an older app over (migration).

Implement the `Recipe` trait (`desktop/src/recipe.rs`). Only `base`, `id`, `name`, `repo`, `blurb`, `glyph`,
`color`, `platform` and `steps` are required:

| Method | Return |
|---|---|
| `platform(system)` | `("full" \| "limited" \| "none", note)` for `"linux"`, `"darwin"` and `"windows"`. |
| `detect()` | `{"installed", "version", "where", "how"}`. Only look; never change anything. Prefer the version the running app reports, then a marker file the recipe wrote. |
| `requirements(op)` | `need(label, ok, hint, blocking, detail)` rows ("what My App needs"). |
| `options(op)` | `option(key, label, "bool"\|"int", value, help)`: the few choices worth asking about. |
| `assets(rel)` | The release files it downloads (for the size shown before starting). |
| `wants(rel)` | Whether a release has this computer's file (skips releases made for other systems). |
| `summary(op, opts, rel)` | The "Orbit will:" lines. |
| `steps(op, opts)` | `step(id, label, weight, fn)` list, for `op` = `"install"` (also used for update and reinstall) or `"uninstall"`. |
| `finish(sess, op, opts)` | `{"headline", "body", "next": [...]}` for the last screen. |
| `needs_admin(op)` | `false`, or a few words on what will ask for the password. |

**Steps use `Session` helpers (`desktop/src/engine.rs`) and nothing else that touches the machine**, so dry runs
stay honest:

| Helper | Use |
|---|---|
| `release_with(repo, wants)`, `asset(rel, name, repo)` | Find the release, and refuse files hosted anywhere else. |
| `download(rel, name, repo, dest)` | Download with progress. Returns the path. |
| `fetch_text(rel, name, repo)`, `verify(path, sums, name)` | Get the checksum file and check the download against it. |
| `place(src, dest)` | Put a program where it goes (atomic rename, made runnable). |
| `write_file(path, text, mode)`, `remove(paths)`, `symlink(target, link)` | Files. `symlink` only replaces another link. |
| `run(argv, ok_codes, quiet, fail, hint)` | Run a program. |
| `admin(argv, what, wait_for, hint)` | Run as administrator: pkexec, else sudo. The system asks for the password; Orbit never sees it. |
| `detail(text)`, `log(text)`, `progress(frac)`, `sleep(s)` | What the progress window shows. |
| `vars`, `var_str(key)`, `opt_bool(key, default)` | State between steps, and the chosen options. |

Every helper respects `--dry-run`. If you add a new kind of change, add it as a helper in `engine.rs` with its own
dry-run branch.

Register the recipe in `desktop/src/recipes/mod.rs` (`pub mod` and the `load()` list). Errors the person sees use
`failed("what happened", "what to do")`.

### Step 4: app page (`desktop/src/apps/my_app.rs`)

Copy `apps/ytdl_ui.rs` (a page for an app with a web page and a service). Use `apps/xmas_tui.rs` instead for
settings Orbit **writes** to the app's own file.

1. Add a `pub fn installed() -> bool` (the program file exists where the recipe puts it).
2. Implement `App` (`apps/mod.rs`):

| Method | Return |
|---|---|
| `id`, `name`, `blurb`, `glyph` (2 letters), `color`, `repo`, `homepage`, `icon` (`"my-app.svg"`) | Who it is. Must match the catalog. |
| `status()` | `{"state": "ok"\|"warn"\|"down"\|"off"\|"unknown", "headline", "version", "running", "facts": [[k, v]], "units", "update"}`. Use `unit_states(self)` and `release_info(self, &version, false)`. |
| `actions()` | `[{"id", "label", "group", "primary"?, "danger"?, "confirm"?, "ext"?}]`. Add `unit_actions(self)` for start/stop/at-login. |
| `run_action(id, args)` | Do it: `open_url(self, url)`, `run_unit_action(self, id)`, or launch the app. Respect `self.ctx.dry_run()`. |
| `settings()` | `[{"title", "fields": [field(...)]}]`. Field types are below. |
| `apply_app_settings(patch)` | Write the changed keys to the app's own settings (in place, atomically: temp file + rename). Skip this when its settings are read-only. |
| **`own_settings()`** | `Some({"id": <an action id>, "label": "My App's own settings", "help": "where they are"})`. Every app has a **settings** button: it shows `settings()` and this button, which opens the app's own settings (its window or page). Return `None` only if the app has none. |
| `units()` | `[(unit, user?)]` (systemd). `windows_task()` for a Windows scheduled task. |
| `open_label()`, `card_actions()` | Optional extra buttons on the overview card while it runs. |
| `logs()` | Default: the first unit's journal. |

Settings field types (`field(key, label, type, value, scope)` plus `with(..., json!({...}))` for extras):
- `bool`, `int` (`min`, `max`), `choice` (`options: [[value, label]]`; more than 5 options shows a list), `text`
  (`pattern`, `patternHelp`, `maxLen`), `words`, `secret`, and `note` (a paragraph).
- `"readonly": true` shows the value without letting it change.
- `scope: "app"` goes to `apply_app_settings`. `"hub"` is kept in Orbit's own settings (for example, the address
  Orbit uses to reach it).

3. Load it in `apps/mod.rs` `load()` next to the others: `if my_app::installed() { apps.push(...) }`.
4. In `server.rs`, `Hub::apps()` reloads the list when an app's installed state changes. Add `my_app` to that
   condition (search for `ytdl_ui::installed()`).

### Step 5: Android (only if the app has an APK)

The catalog entry from step 1 is enough to list, install and update it. Android Orbit verifies the APK against the
release checksums and Android's own signature check. If the app's releases carry a signature file, add a built-in
`Listing` with `signature` and `signingKey` in `android/.../Catalog.kt` (keys are never read from the catalog). Also
add the app's assertions to `android/app/src/test/.../CatalogApplyTest.kt`.

### Step 6: translations, tests, docs

1. `python3 tools/i18n.py check`, then translate every missing text into all languages (§6).
2. `tests/test_catalog.py` checks that the catalog is current and that something installs every app: rerun it.
3. Add Rust unit tests for anything parsed (versions, settings files) in the module's `#[cfg(test)] mod tests`.
4. Add the app to `tools/ci-nova-windows.py --exe` (the Windows real-machine check) if it runs on Windows. CI
   installs, reinstalls and removes it for real on GitHub's machine.
5. Update `README.md`: the apps table and *What each app gets*. Add a line to `packaging/release-notes.md`.

## 5. How some features work (so you change them in the right place)

- **Short patch notes on update.** `desktop/src/notes.rs` (desktop) and `android/.../Notes.kt` (Android) apply the
  same rules. They keep the top-level `- ` items of the part of a release's notes about that version. That is a
  `### What's new` / `### New` / `### Fixed` section, or a `**New in X.Y.Z**` block when one text covers several
  versions. They stop at a downloads table (`| … |`) or an "Updating from…/Install…" heading. Each item is shortened
  to its **bold title**, or else its first sentence (140 characters at most). They show 5 items per version and up
  to 3 versions. **To get good notes in Orbit, an app's release notes should be a bullet list with a short bold
  title per item.** The installer window shows them (`notes` in `recipe::info`). "full notes ↗" opens the release
  page through `/api/install/<id>/notes-page`, which only opens URLs from that app's own repository.
- **Side bar.** It shows only apps installed here, or that answer from elsewhere. The hub setting `navAll` shows all
  of them. Every enabled app keeps its overview card, so it can be installed from there.
- **Settings button.** Every installed app's card and page has one. `settingsDlg()` in `index.html` draws
  `settings()` with `fieldRow()`, plus `ownSettings` from `own_settings()`.
- **Themes.** A theme is a block of CSS tokens (`--bg`, `--raise`, `--text`, `--muted`, `--accent`…) in
  `index.html`. Use the tokens and never hard-code colours. Lists (`select.inp`) and link buttons (`.lnk`) are drawn
  by Orbit, not the system, so they follow the theme. `matchScheme()` sets `color-scheme` from the background so the
  system's own parts match it. Any new control needs the same treatment: test it on a dark theme and on `paper`.
- **Icons.** The icons in `orbit/static/apps/` are built into the program (`desktop/build.rs` → `APP_ICONS`). The
  catalog inlines them as SVG for every Orbit, including Android (up to 64 KB each).

## 6. Translations (required for every UI text change)

Orbit translates text where it is shown: the page (MutationObserver), the Android `Txt` and the Rust notifications.
`tools/i18n.py` extracts the English from `index.html`, `desktop/src/**/*.rs` (outside tests), the Android `*.kt` and
the catalog.

1. `python3 tools/i18n.py missing <code>` for each of `es fr de pt-BR it ru ja zh-CN ko` (usually the same list for
   all).
2. Translate. `{}` is a changing part: keep the same number. Use `{1} {2}` to reorder. Keep product names, commands,
   paths and symbols (`·`, `↗`, `──`) as they are. Keep the tone terse and use lowercase labels where the language
   allows.
3. `python3 tools/i18n.py merge <code> <list-file> <translations-file>` for each, then `python3 tools/i18n.py sync`
   and `check`.

**Rules that keep extraction working:**
- Use template literals in JS (`` `update to ${v}` ``), not `"update to " + v`.
- Write no CSS `content:` text: use `attr(data-…)`.
- Mark text that must stay as it is (an app's own output, release notes, terminal) with `data-no-tr` in HTML, or
  `raw = true` for Android `Txt`.
- A source file with no UI text of its own (it only *matches* words) goes in `NO_TEXT` in `tools/i18n.py`.

## 7. Releasing Orbit

The details are in `RELEASING.md`. The short version:

1. Bump the version in `desktop/Cargo.toml`, `desktop/tauri.conf.json` and `orbit/__init__.py`, then
   `cargo build` (updates `Cargo.lock`).
2. Add a `**New in X.Y.Z**` section at the top of `packaging/release-notes.md` (what's new, for users, as bold-titled
   bullets).
3. `python3 tools/sync-icons.py && python3 tools/make-catalog.py`. All tests must pass.
4. Push to `main`. When the *build* and *test* workflows are green on that commit, tag it:
   `git tag -a vX.Y.Z -m "Orbit vX.Y.Z" && git push origin vX.Y.Z`. Tags `vX.Y.0` (milestones) also build ARM and
   macOS.
5. The tag build publishes the release without the Android app, because the signing key isn't in the repository. The
   maintainer signs `orbit-android-unsigned.apk` locally (`tools/sign-apk/Sign.java`). They upload it as
   `orbit-android.apk` and `orbit-vX.Y.Z-android.apk`, and add both lines to `SHA256SUMS`.
6. Run the *self-update-from-a-release* workflow: the previous release updates itself to the new one on every system.

A release isn't needed for catalog-only changes (names, icons, blurbs, Android listings): pushing to `main` is enough.

## 8. Pitfalls already met (don't repeat them)

- `gh run list -c <sha>` needs the full SHA.
- GitHub's release list isn't newest-first: always sort by version (`net::version_tuple`).
- An app that replaces its program while it runs: write it next to the old one and rename it over (`Session::place`).
  Never delete the running file.
- WebKitGTK (the Linux window) draws native form controls in the system's light style. Every control needs the
  `appearance: none` styling from §5.
- Plurals: `"1 update"` and `` `${n} updates` `` are two texts. Never use `"update" + (n > 1 ? "s" : "")`.
- The Android catalog limits each icon to 64 KB and each blurb to 300 characters. Anything bigger is ignored and the
  built-in copy shown.
